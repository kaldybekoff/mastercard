# Описание кейса — MDQ 2026

## Problem Statement

На рынке существует группа самозанятых и предпринимателей, которые ведут коммерческую деятельность через обычные потребительские карты. Они регулярно получают платежи от множества контрагентов, делают частые POS-покупки, характерные скорее для малого бизнеса, чем для типичного потребителя.

**Задача:** Разработать ML-алгоритм (predictive-модель), который по транзакционному поведению обнаруживает скрытую коммерческую активность среди клиентов-физлиц.

---

## Бизнес-цели

1. **Рост доходов от транзакций и эквайринг** — бизнес-карты имеют иные тарифы, комиссии и возможности монетизации (включая POS-эквайринг и сервисы для торговли)
2. **Кросс-продажи** — кредитование оборотного капитала, зарплатные проекты, торговый эквайринг, кассовые решения

---

## Данные

> ⚠️ Данные полностью синтетические. Предназначены исключительно для учебных целей.

### Файлы

| Файл | Размер | Описание |
|------|--------|----------|
| `business_cards_MDQ.parquet` | ~50MB | 25K карт, ~3M транзакций |
| `consumer_cards_MDQ.parquet` | ~150MB | 80K карт, ~10M транзакций |
| `merchants_reference.parquet` | ~44KB | Справочник ~2K мерчантов |

**Период данных:** 1 октября 2025 — 31 марта 2026 (6 месяцев)  
**Основная валюта:** Тенге (KZT)  
**География:** Казахстан + международные транзакции

---

## Схема таблиц

### Транзакции (business_cards + consumer_cards)

| # | Колонка | Тип | Описание |
|---|---------|-----|----------|
| 1 | `transaction_date` | date | Календарная дата транзакции |
| 2 | `transaction_timestamp` | datetime | Дата и время с точностью до секунды |
| 3 | `transaction_amount_kzt` | float | Сумма транзакции в тенге |
| 4 | `mcc` | int | Merchant Category Code (ISO 18245) |
| 5 | `merchant_id` | str | ID мерчанта (формат MER_######) |
| 6 | `channel` | str | online / offline |
| 7 | `bank_name` | str | Банк-эмитент карты |
| 8 | `country` | str | Страна транзакции (страна эквайрера) |
| 9 | `card_number` | str | 16-значный номер карты |
| 10 | `card_tier` | str | Продуктовый уровень карты |
| 11 | `tokenized` | bool | Apple Pay / Samsung Pay |
| 12 | `Is_recurring` | bool | Регулярный платёж (подписка/авто-биллинг) |

### Мерчанты (merchants_reference)

| # | Колонка | Тип | Описание |
|---|---------|-----|----------|
| 1 | `merchant_id` | str | Уникальный ID (MER_######) |
| 2 | `merchant_name` | str | Название мерчанта |
| 3 | `mcc` | int | MCC категория |
| 4 | `merchant_country` | str | Страна регистрации мерчанта (≠ country в транзакциях) |
| 5 | `recurring_capable` | bool | Способен выставлять регулярные платежи |

---

## Целевая переменная

В явном виде в данных **отсутствует**.

- `business_cards` — известный позитивный класс (ground truth = бизнес)
- `consumer_cards` — **смесь** настоящих потребителей и скрытых предпринимателей

Это задача **Positive-Unlabeled (PU) Learning**.

---

## Ключевые ограничения данных

1. **Только outflow** — в данных только исходящие транзакции. Входящие P2P-переводы (главный сигнал реального предпринимателя — получение платежей от клиентов) **недоступны**.
2. **Синтетика** — паттерны могут не полностью отражать реальное поведение.
3. **Нет demographic данных** — возраст, регион, профессия неизвестны.
